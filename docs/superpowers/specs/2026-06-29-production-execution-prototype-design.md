# 生产执行与扫码绑定原型设计

## 目标

在现有 `生产计划/index.html` 单页原型中，保持当前 480×800 PDA 蓝色工业风和生产执行导航结构，将“扫码绑定”页面调整为与现行 Android 业务一致的可交互演示，并补齐开发说明。

## 范围

- 生产执行总览保留三个工位卡片、进度、状态和“结束生产”入口，仅校准扫码绑定卡片的描述与进度表达。
- 扫码绑定使用同一页面内的两步状态：先扫描成品码，再连续扫描关键部件 SN。
- 不改整体测试、流转单打印及独立的“成品关键件换绑”模块。
- 原型使用静态 Mock 数据模拟接口结果，不连接真实后端。

## 页面与交互

### 1. 等待扫描成品码

- 顶部标题、工单与产品号沿用现有生产执行样式。
- 右上角显示“重置”；在任意扫码绑定状态点击后，回到等待扫描成品码。
- 扫码框仅接受成品码，点击“扫码”或按 Enter 执行。
- 成功后模拟调用 `/pro/proPlaDtl/snBindInfo`，加载当前产品信息和两级关键部件列表；同时模拟调用 `/pro/proPlaDtl/bindProgress` 刷新计划绑定进度。
- 失败时以醒目错误提示展示后端 message，并保留、全选扫码内容便于重扫。

### 2. 绑定关键部件

- 扫码框直接将原始扫描值作为 `matSn` 传给 `/pro/proPlaDtl/bind`，不调用二维码解析接口。
- 常规扫码固定使用 `operateType=1`。
- 成功后提示“绑定成功”，随后刷新 `/bindProgress` 和 `/snBindInfo` 所对应的页面数据。
- 关键部件采用两级列表：一级展示物料号、物料名称、用量和完成数；二级展示已核对 SN，每个已绑定 SN 提供删除入口。

### 3. 换绑

- 当 `operateType=1` 返回非空 `boundMatSns` 时，打开项目风格的单选弹窗。
- 选择待替换 SN 后再次模拟请求：`matSn=本次扫描值`、`changeMatSn=所选旧 SN`、`operateType=3`。
- 未选择候选项时不允许确认；取消弹窗不改变已有绑定。
- 换绑成功后关闭弹窗、提示成功，并刷新进度与绑定详情。

### 4. 解绑

- 点击二级列表中的删除按钮后执行确认。
- 确认后模拟请求：`matSn=当前列表 SN`、`changeMatSn=null`、`operateType=2`。
- 成功后提示“解绑成功”，并刷新进度与绑定详情。

## 状态与校验

- 空输入：提示扫描内容不能为空，保持扫码框焦点。
- 未加载成品时扫描关键部件：提示先扫描成品码。
- 已加载成品后再次扫描成品码：作为不匹配数据交由绑定接口反馈，不自动切换产品。
- 重复扫描当前已绑定 SN：展示接口错误，不重复加入列表。
- 非当前 BOM、SN 不存在、已绑定其他成品、数量超限：展示接口 message，扫码框内容全选。
- 请求处理中禁用重复操作，避免连续扫码产生重复请求。
- 所有成功动作都以接口业务码 `code=200` 为准，不依赖 `data` 是否为 0 或空值。
- 重置只清理当前页面的成品上下文和临时提示，不执行解绑，也不修改服务端绑定数据。

## 原型说明区

扫码绑定详情底部保留开发说明，但内容更新为：页面状态、三个接口、`operateType` 参数、换绑候选逻辑、解绑逻辑、校验反馈、成功刷新顺序、重置边界和 Mock 测试码。旧的“清空当前页面”“返回扫描下一个”按钮及其旧逻辑删除。

## 验收标准

- 总览进入扫码绑定后，默认处于扫描成品码状态。
- 成品码成功后出现绑定进度和两级关键部件清单。
- Enter 与扫码按钮都可触发扫描。
- 常规绑定、候选单选换绑、删除解绑、错误反馈和右上角重置均可在原型内演示。
- 操作说明与 Android 当前接口规则一致，且不混入后生产阶段的独立关键件变更流程。
