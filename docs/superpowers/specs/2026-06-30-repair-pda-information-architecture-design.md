# 不良维修 PDA 信息架构优化设计

## 目标

将 `RepairActivity` 的首屏从完整详情与表单混排，收缩为“扫码结果确认 + 维修操作入口”。现场人员首屏只需确认当前 SN、维修状态、不良现象、不良说明以及下一步动作；追溯、历史和照片信息通过右上角更多菜单访问。

扫码校验、字典加载、拍照上传、草稿保存、正式提交和成功后清空流程保持不变。

## 页面结构

### 扫码确认页

- 顶部标题保持“不良维修”，保留“刷新”，增加更多菜单入口。
- 扫码卡保留 SN 输入、清空能力、校验中状态和“已带出不良记录”成功提示。
- 扫码成功后只展示一张紧凑核心卡：SN、状态 Tag、不良现象、不良说明。
- 不良说明默认最多三行，支持展开和收起。
- 核心卡底部只保留主动作“填写维修结果”。
- 来源、单号、批次、物料、测试物料、上报人、上报时间、处理轨迹和照片数量不在首屏出现。

### 维修填写页

- 仍由 `RepairActivity` 承载，通过同一 Activity 内的页面状态切换进入，避免迁移现有业务逻辑。
- 保留维修结果、不良原因、维修人、维修说明、照片上传、保存和提交控件及原有校验规则。
- 点击系统返回键或工具栏返回时，优先回到扫码确认页；不清除当前扫描结果和已填写内容。
- 保存或提交成功后沿用现有清空页面逻辑，返回待扫描状态。

### 更多菜单

扫码成功后提供：

- 查看详情信息
- 查看处理记录
- 查看维修照片
- 清空 / 重新扫描

无有效扫码结果时，详情、记录和照片入口给出“请先扫描 SN”提示；清空入口仍可恢复待扫描状态。

### 详情信息页

- 新增独立详情页，只展示本次扫描已经返回的数据，不增加网络请求。
- 使用分组卡片展示 SN、来源、单号、批次、物料、测试物料、不良现象、不良说明、上报人和上报时间。
- 不良说明默认三行，可展开和收起。

### 处理记录页

- 沿用现有 `RepairHistoryActivity` 和日志请求，不改变接口。
- 将当前大段文本改为“上报信息摘要 + 时间轴处理卡片”。
- 每条记录显示操作名称、时间、操作人和内容；当现有 `opDesc` 中包含“状态：xxx”时，将状态从内容中拆出并显示为 Tag，不虚构后端未返回的状态。
- 页面不再重复完整详情；详情由独立详情页承载。

### 维修照片

- 更多菜单中的照片入口复用当前扫描记录和本次维修过程中已上传的照片。
- 以紧凑缩略图列表展示，点击仍使用现有大图预览能力。
- 照片上传仍位于维修填写页，避免改变操作顺序。

## 视觉规则

- 延续现有蓝色企业 PDA 工具栏和 JiangCore 组件体系。
- 页面背景使用浅灰色，内容使用白色圆角卡片。
- 不良现象使用红色强调；“待维修”使用橙色状态 Tag；次要字段使用灰色小字。
- 卡片间距、内边距和标题字号收紧，优先保证 480×800 PDA 首屏能完整看到扫码区、核心卡和主操作按钮。
- 不引入第三方依赖，不新造一套全局样式，不修改无关页面。

## 状态与数据流

1. 扫描 SN 后继续调用现有 `scanValidRepairSn`。
2. 成功结果继续转换为 `RepairUiState`，首屏渲染核心信息并缓存完整报告。
3. “填写维修结果”只切换视图状态；原有已选结果、原因、维修人、说明和照片集合继续由 `RepairActivity` 持有。
4. 保存、提交和照片上传继续调用现有 ViewModel 方法。
5. 详情页、处理记录页和照片入口只消费当前报告或现有日志接口，不引入新的业务分支。

## 验证范围

- 未扫描、校验中、校验失败、校验成功四种首屏状态。
- 不良说明三行收起与完整展开。
- 更多菜单四个入口及无扫描状态提示。
- 确认页与填写页往返后输入内容不丢失。
- 草稿保存、正式提交、照片上传与删除、成功后清空行为保持原样。
- 详情字段映射正确，处理记录时间轴能覆盖空列表和多条记录。
- 480×800 PDA 尺寸下无关键控件挤压或被遮挡。
