# 批次调试不良数超限提示设计

## 目标

在 `DebugTaskExecuteActivity` 正式提交单个 SN 成功后，检查调试计划累计不良数是否严格大于计划不良数上限。若超限，则在手持终端提示操作员选择“联系主管”或“继续工作”。两种选择都允许继续批次调试，但保存不同的操作日志。

## 范围

- 仅服务批次调试执行页 `DebugTaskExecuteActivity`。
- 不修改单机调试、返检或维修流程。
- 不修改检查项渲染、输入校验、NG 现象选择、草稿保存和批次完工规则。
- 不新增页面布局；复用现有确认弹窗组件。

## 数据来源与触发时机

当前批次信息 `DebugTaskItemInfoDto` 提供批次级 `ngCount` 和所属计划 `taskId`，但客户规则针对计划累计不良数。计划级数据以 `DebugPlanDetailDto.ngCount` 和 `DebugPlanDetailDto.rejectionQty` 为准。

触发流程：

1. 操作员正式提交单个 SN，且提交成功。
2. 页面刷新批次信息，从最新批次信息取得 `taskId`。
3. 页面请求最新调试计划详情。
4. 当 `ngCount > rejectionQty` 且当前页面会话尚未处理过超限提示时，显示弹窗。

以下情况不触发：

- `ngCount <= rejectionQty`。
- 保存草稿成功。
- 首次进入页面或普通手动刷新。
- 当前页面会话已经选择过一次处理方式。

## 弹窗交互

- 标题：`批次不良数已超限`
- 内容：`当前调试计划不良数为 {ngCount}，已超过计划上限 {rejectionQty}，请选择后续处理方式。`
- 操作一：`联系主管`
- 操作二：`继续工作`

任一操作被选择后：

1. 立即将当前页面会话标记为已处理，避免再次弹窗。
2. 关闭弹窗并恢复扫码操作，不阻断后续批次调试。
3. 调用调试日志保存接口记录选择。

“当前会话”指本次 `DebugTaskExecuteActivity` 实例。退出并重新进入同一批次后，可以再次触发提示。

## 日志接口

- 请求：`POST /m/iqcTaskOpLog/addLog`
- 请求体字段：`taskId`、`taskItemId`、`opName`、`opDesc`

选择“联系主管”时：

- `opName`：`批次不良超限-联系主管`
- `opDesc`：`当前批次不良数为 {ngCount}，已超过计划上限 {rejectionQty}；操作员已知晓并选择联系主管，继续批次调试。`

选择“继续工作”时：

- `opName`：`批次不良超限-继续工作`
- `opDesc`：`当前批次不良数为 {ngCount}，已超过计划上限 {rejectionQty}；操作员已知晓并选择继续工作。`

日志使用“选择联系主管”，不表述为“已联系主管”，避免记录超过实际动作。

说明：日志中的 `{ngCount}` 使用计划详情返回的计划累计不良数。虽然文案沿用客户口径“当前批次”，判断数据仍以计划累计值为准。

## 代码结构

### 数据与网络层

- 新增日志请求 DTO，字段名严格保持接口契约。
- `ZdsApi` 增加日志保存接口。
- `ZdsRepository` 增加对应仓库方法，继续使用现有网络调用封装。
- `ZdsViewModel` 暴露日志保存方法及独立的成功/失败结果，避免与 SN 提交完成信号混淆。

### 页面层

`DebugTaskExecuteActivity` 增加以下会话状态：

- 当前正式提交成功后是否等待执行计划级超限检查。
- 当前页面会话是否已经处理过超限提示。
- 待保存或待重试的日志内容。
- 日志是否已经执行过一次后台重试。

页面继续沿用现有“SN 提交成功后刷新批次信息”的流程，只在该流程后追加计划详情刷新与超限判断。

### 规则层

将是否提示的判断抽为无 Android 依赖的纯规则：

```text
shouldWarn = submittedSuccessfully
    && !sessionAcknowledged
    && planNgCount > rejectionQty
```

草稿保存不进入该规则。

## 失败处理

- SN 提交失败：沿用现有失败处理，不检查计划超限。
- 批次信息或计划详情刷新失败：不阻断扫码；本次不弹窗，下一次正式提交成功后重新检查。
- 日志首次保存失败：提示日志保存失败，但不阻断操作、不重复弹窗；保留日志内容，在下一次 SN 正式提交成功后后台重试一次。
- 后台重试仍失败：结束本会话内的自动重试，避免无限请求；不改变本会话已处理状态。

## 测试与回归

规则单元测试至少覆盖：

- `ngCount < rejectionQty`：不提示。
- `ngCount == rejectionQty`：不提示。
- `ngCount > rejectionQty`：提示。
- 已在当前会话处理：即使仍超限也不提示。
- 保存草稿：不触发检查。
- 两个选项生成不同的 `opName` 和对应 `opDesc`，并携带正确的 `taskId`、`taskItemId`、计划不良数和上限。

手工回归：

- 正常 SN 提交流程和扫码焦点不受影响。
- NG 现象选择仍在 SN 提交前完成。
- 日志请求进行中仍可继续扫码。
- 退出并重新进入批次后，会话状态重置。
- 保存草稿、批次完工、照片上传和输入校验行为保持不变。
