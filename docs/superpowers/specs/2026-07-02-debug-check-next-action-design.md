# 调试检查下一项动作设计

## 目标

调试检查项较多时，操作员无需反复收起软键盘并手动寻找下一条。软键盘“下一项”和 PDA 实体确认键统一触发静默校验导航：优先定位未完成项，全部完成后进入现有提交流程。

## 适用范围

- 批次调试。
- 单机调试。
- 返检。
- 整机测试。

四个业务继续按照接口数组原始顺序展示和查找检查项。

## 触发方式

- 数值输入框收到软键盘 `IME_ACTION_NEXT`。
- 数值输入框收到 PDA 实体确认键 `KEYCODE_ENTER`。

扫码输入框、文本输入弹窗和其他弹窗中的 Enter 不触发检查项导航，避免干扰扫码和弹窗确认。

## 导航规则

1. 从接口顺序中的检查项里查找第一条 `PENDING` 且不可跳过的项目。
2. 找到未完成项时：
   - 不显示“还有未完成项”的 Toast。
   - 滚动到该检查项。
   - 若为数值输入项，自动聚焦输入框并保持或唤起软键盘。
   - 若为文本、确认或拍照项，仅定位到该行，由操作员完成对应动作。
3. 没有未完成项时，调用当前页面已有提交方法。
4. 提交流程保持原规则：存在 NG 时选择不良现象，无 NG 时直接提交。

数值超范围产生的 `FAIL`、确认不合格和其他 NG 都属于已操作结果，不视为未填写。

## 实现边界

- 共用检查项 Binder 增加“下一项动作”回调，只监听数值输入框的 IME Next 和实体 Enter。
- 四个业务页面分别复用自身已有的检查项状态和提交方法。
- 抽取纯规则查找第一条未完成项，增加单元测试。
- 不修改接口、DTO、列表顺序、提交参数和页面布局。

## 回归检查

- 空白数值项不能被跳过。
- `isSkipable=true` 的空白项不阻断导航或提交。
- 已填写但结果为 NG 的项目不被当作未完成项。
- 扫码枪提交 SN 的 Enter 行为保持不变。
- 弹窗输入和确认行为保持不变。
