# 维修提交后快速复检设计

## 目标

正式提交维修结果成功后，让操作员明确选择继续维修下一台，或携带当前原始二维码直接进入复检，减少重复扫码。

## 成功后分支

- 保存草稿 `DRAFT` 成功：保持现有提示与清空行为，不弹出复检选择。
- 正式提交 `SUBMIT` 成功：不立即清空，显示不可从外部取消的双按钮弹窗。
- 弹窗左侧为“继续维修”：清空维修页，返回待扫描状态并聚焦扫码框。
- 弹窗右侧为“去复检”：先保存维修页扫码框中的原始 SN/PRO 二维码，再清空维修页并进入 `RecheckActivity`。

## 复检接入

- 为 `RecheckActivity` 增加显式 `start(context, qrCode)` 入口。
- 入口参数必须使用维修扫码框原始内容，不使用接口返回的纯 `report.sn`。
- 复检页创建时将二维码写入现有扫码框，并在页面初始化完成后直接调用现有 `submitScanSn`，自动执行复检校验。
- 手动进入复检页、手动输入和普通扫码行为保持不变。

## 状态与异常

- 弹窗展示期间不重复提交。
- 若传入二维码为空，复检页保持普通待扫描状态，不自动请求。
- 复检校验失败时继续沿用现有扫码错误提示和重新聚焦逻辑。
- 不修改维修提交接口、复检接口、ViewModel、Repository 或 DTO。

## 验证

- `DRAFT` 成功仍提示保存并清空。
- `SUBMIT` 成功只显示一次选择弹窗。
- “继续维修”清空页面并可继续扫码。
- “去复检”传递原始 SN/PRO 二维码，复检扫码框正确回显并自动发起校验。
- 复检页无启动参数时保持原行为。
